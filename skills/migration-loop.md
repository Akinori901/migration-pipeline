# 移行ループ

移行対象のドメインを1つずつ処理し、**全ドメインが終わるまで自律的に進む**ループ。

## なぜループにするのか

移行は「エンドポイント数 × 検証項目数」の掛け算になり、1会話では終わりません。
かといって人間が毎回指示を出すと、今度は人間がボトルネックになります。

このループは次の3つで、その両方を避けます。

- **ドメインごとにエージェントを使い捨て起動する** — 前ドメインの文脈を持ち越さない
- **成果物はファイルで受け渡す** — 会話に全文を載せない
- **判断が要る時だけ止まる** — それ以外は進み続ける

結果として、**メイン会話が保持するのはドメインごとのタグ集計サマリーだけ**になり、
数十ドメインを流してもコンテキストが枯渇しません。

## 前提

- `migration.config.yml` に旧・新システムの構成があること
- スケジュールファイル（既定 `docs/schedules/migration.md`）にドメイン一覧があること

スケジュールファイルは**状態管理の唯一の正**です。形式は次のとおり。

```markdown
| ドメイン | トリアージ | 対処 | 備考 |
|---------|----------|------|------|
| orders  | [x]      | [x]  | 完了 |
| items   | [ ]      | [ ]  |      |
| users   | [ ]      | [ ]  |      |
```

## 実行フロー

```
① スケジュールファイルを読む
     ↓
② 次の未着手ドメインを特定する（トリアージ列が [ ] のもの）
   未着手がなければ「全ドメイン完了」を報告して終了
     ↓
③ そのドメインについて migration-pipeline の手順を実行する
   - 専門エージェントを Agent ツールで直接起動する
   - 各エージェントの成果物はファイルで受け渡す（会話に全文を持ち込まない）
   - 完了したらスケジュールファイルのチェックボックスを更新する
     ↓
④ 結果を受け取る

   【止まるケース】→ ユーザーに報告して待機
   - [パス変更] タグが含まれる → どちらを正とするか判断を仰ぐ
   - [ロジック欠落] の補完実装の承認が必要
   - 判定不能と報告されたエンドポイントがある
   - エラー・ブロッカーが発生した

   【続行ケース】→ ② に戻る
   - [正常] / [FE変更漏れ] / [BE欠損] のみで修正・検証が完了している
     ↓
⑤ 全ドメイン完了時に進捗サマリーを報告して終了
```

### エージェント起動についての制約

**サブエージェントはさらに子エージェントを起動できません。**
そのため「まとめ役エージェントを起動し、その中から専門エージェントを起動する」
という二重ネストにはできません。

専門エージェントの起動は**必ずメイン会話から**行い、
メイン会話自身がまとめ役を兼ねます。これは実装上の制約であって好みではありません。

## 報告フォーマット

### 1ドメイン完了時（続行）

```
✅ {ドメイン} 完了
- 検出タグ: [正常] x件 / [FE変更漏れ] x件修正済 / [BE欠損] x件実装済
- 次: {次のドメイン} に進みます
```

### 止まる時

```
⏸ {ドメイン} で判断が必要です

【要確認EP一覧】
- [パス変更] GET /api/xxx/yyy
  旧システム: /api/old/path
  新システム: /api/new/path
  → フロント側を新パスに合わせますか？
    それとも新システム側にエイリアスを追加しますか？

ご判断後に /migration-loop で再開してください。
```

### 全完了時

```
🎉 全ドメイン完了
- 処理ドメイン数: x
- タグ別集計: [正常] x / [FE変更漏れ] x / [BE欠損] x / [パス変更] x / [ロジック欠落] x
```

## 重要ルール

- **エージェントはドメインごとに使い捨て起動する。**
  前ドメインのコンテキストを持ち越さない。
  メイン会話が保持するのはタグ集計サマリーのみ。
- **スケジュールファイルが唯一の状態管理。**
  再開時は必ずファイルを読んで状態を復元する。会話の記憶に頼らない。
- **止まったら必ず理由を明示する。** 黙って止まらない。
- **再開は同じコマンドを呼ぶだけ。**
  ユーザーが判断を返した後、`/migration-loop` で続きから再開できる。
- **自動で判断しない。**
  `[パス変更]` と `[ロジック欠落]` は仕様に関わるため、必ず人間に確認する。
  ここを自動化すると、静かに仕様が変わる。
